**Root cause:** Vite fingerprints build assets with a content hash (`-BJHyOYnu`, `-CfpWkI3Q`, etc.) that changes every deployment. A URL pointing at your own build output will 404 after the next rebuild. Never reference `srivelan.vercel.app/assets/...` in content data — always use an externally hosted, stable URL (ImgBB, Cloudinary, GitHub raw, or Firebase Storage).

## Notes on how images are actually served on the live site

- The live site's content (including these image URLs) is loaded from **Firestore** at runtime, seeded originally from `src/data/defaultContent/sections.ts`.
- Fixing a URL in `sections.ts` alone does **not** fix already-published Firestore data — you must also re-save the corrected value via **Admin Dashboard → Services / Governing Board tabs**, or use "Restore to Default" after deploying the code fix.
- `src/data.ts` holds the static/original values; these are correct and match most of the working URLs above.
